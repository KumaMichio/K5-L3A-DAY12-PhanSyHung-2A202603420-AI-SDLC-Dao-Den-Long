## 2. What worked with AI

- **Spec first, stored verbatim.** Each ticket was saved word for word in `docs/specs/` before any code, with our own "agent notes" kept separate. The agent re-read exact numbers instead of paraphrasing, and the evidence tables reference ticket sections.
- **Deterministic core separated from rendering** (one `Sim` used by headless, web and bench). Every rule became testable in milliseconds; a full night runs in about 0.2 s.
- **Tests written from hand-computed expectations** (e.g. win score 598 = 5×10+100+298+150). They found real bugs: the dash's last tick at walking speed, a drifter vanishing one tick early, the Night 3 start inside the tower.
- **Proof regenerated by script, never by hand**, with CI diffing it. Phase 4's proof being byte-identical to Phase 3's showed in one line that the bench switches change nothing.
- **A change request handled through an ADR**: the fuel state model was written down before editing, so tests for replaced rules were updated or deleted with reasons rather than skipped.

## 3. What did not work / where the AI was wrong, and how it was caught

| AI mistake | How it was caught | Fix |
|---|---|---|
| Night 3 default start (0,0,0) inside the bell tower | First full-night run lost in 300 ticks | Assumption A-M1 + a test |
| Dash last tick at run speed | While working out a test's expected values | Code fix |
| Zero-intensity PointLight on every shade (from Phase 2) | WebGL shader errors with 200 shades in the bench | Removed |
| One mesh per shade part | Bench at 7 FPS | Instanced rendering |
| Blocking memory probe in the bench | Bench hung; polling the page showed frames fine | Async probe |
| Several tests asserting the wrong thing (held key after respawn, walking off a 4 m bridge, strict `<` on rounded output, a top-10 cutoff) | Failing tests read before changing code | Test fixes, explained in the notes |
| Fragile shell edits (heredoc quoting, a `sed` comment inside an object) | Build/parse errors; `git diff` showed nothing half-applied | Patch scripts saved as files |
| The Stop hook first ran tests from a lowercase `e:\` path (Vitest crash) | The hook blocked even though tests passed by hand | `scripts/stop-gate.mjs` with canonical paths and real output |
| Claimed the dev server was stopped while a child process kept running | Found port 5174 still busy later | Disclosed to the user |

## 4. Which harness helped most

1. **`CLAUDE.md` "Current phase" block**: one paragraph naming the spec, what it replaces, and the hard rules (12-step order, maps as data, fuel units). It was updated every phase (git history shows it).
2. **Stop hook (`scripts/stop-gate.mjs`)**: the agent could not finish with red tests. After its own fix it printed the failing output, which made it actionable.
3. **`scripts/proof.mjs` + CI diff**: evidence that can't drift from the code at a tag.
4. **`verify-phase` skill**: a checklist for tagging (tests → proof → full-night timing → evidence table).

**How tokens were saved:**
- Specs read once and stored in the repo.
- Small targeted patches instead of re-reading big files.
- Long runs (soak, bench, proof) produce compact JSON summaries.
- Fixes started from failing-test output rather than exploratory runs.
- No sub-agents.

**What wasted tokens:**
- Shell-quoting failures on large heredoc patches; writing patch files from the start would have been cheaper.
- Rewriting `main.ts` in full twice.

## 6. If I did it again

- Look at the game in a real browser (screenshot script) from Phase 1, not Phase 4. The first actual look at the UI came in the last phase.
- Use instanced rendering for crowds from the start, and budget draw calls and lights per entity.
- Set up headless browser screenshots plus an FPS check in CI early, so "not verified visually" never piles up.
- Log tokens per phase at tag time rather than at the end.
